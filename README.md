# Абан Метео v4 — Супер-ансамбль, Архив ERA5 и Прогноз 35 дней

Мобильное и десктопное **PWA-приложение (Progressive Web App)** для метеомониторинга **п. Абан (Красноярский край, станция ВМО 29485, 56.68°N, 96.07°E, высота 246 м, UTC+7 `Asia/Krasnoyarsk`)**.

Приложение работает **полностью на клиенте (Zero-Backend)**, собирается без Node/Webpack (чистые нативные ES-модули) и готово к публикации на **GitHub Pages** с поддержкой офлайн-кэша.

---

## Возможности v4

- **Супер-ансамбль (до 6 источников):**
  - **Google WeatherNext 3** (`weather.googleapis.com/v1`: текущие условия, 10 дней прогноза, 240 часов почасово, 24 часа истории).
  - **Open-Meteo Multi-Model:** `ECMWF IFS 0.25°`, нейросетевая `ECMWF AIFS 0.25°`, `DWD ICON Seamless`, `NOAA GFS Seamless` (14 дней прошлого + 16 дней прогноза).
  - **Companion `best_match`:** вероятность осадков, высота снежного покрова и 4-слойный профиль температуры почвы (`0 / 6 / 18 / 54 см`).
  - **MET Norway (`locationforecast/2.0`):** опциональный независимый скандинавский ориентир.
  - **Качество воздуха (Air Quality API):** `PM2.5`, `PM10`, `CO`, `European AQI` и оценка риска смога при инверсии.
- **Динамическая калибровка MOS (14-дневный скользящий контроль):**
  - Автоматически сравнивает прошлые запуски (`previous-runs-api.open-meteo.com`, `day-1` / `day-2`) с последующим анализом той же модели за 14 дней по дневным и ночным окнам.
  - Считает `MAE`, систематическое смещение (`Bias`) и корректирует вес каждой модели в ансамбле с экспоненциальным затуханием по горизонту (`exp(-offset/4)`).
  - **Важно:** эталон — собственный анализ модели, а не наблюдения станции ВМО 29485. `MAE` здесь показывает согласованность прогонов и годится для взвешивания моделей, но не является оценкой абсолютной точности прогноза.
- **Горизонт 35 дней и вероятностный веер `P10–P90`:**
  - Агрегирует ансамбли `ECMWF IFS Ensemble` (до 16 дн.) и `NOAA GEFS / Seasonal` (до 35 дн.) в компактные квантили `P10 / P25 / P50 / P75 / P90` (без хранения тяжёлых массивов членов в `localStorage`).
  - На днях 17–35 применяет регуляризацию к 30-летней климатической норме ВМО 29485 (1991–2020) и рассчитывает вероятности мороза `≤ -20°C` и сильных осадков `≥ 5 мм`.
- **Исторический архив ERA5-Land с 1940 года:**
  - Произвольный выбор дат с `1940-01-01` по сегодняшний день с бесшовной склейкой 5-дневного лага ERA5 через оперативный архив `forecast?past_days=14` и 5-слотовым LRU-кэшем.
- **Прикладная метеофизика для п. Абан:**
  - Термодинамическая фаза осадков по температуре смоченного термометра Стала (`Tw`): снег, мокрый снег, гололёд / ледяной дождь, дождь.
  - Векторное осреднение ветра `(u, v)` + лапласовский пересчёт давления (высота 246 м Абан vs уровень моря).
  - Индикаторы полевой обстановки: риск гололедицы на **Р-255**, марка дизельного топлива (летнее / межсезонное / зимнее / арктическое), глубина промерзания почвы и расчёт котловинной радиационной инверсии.
- **Автономность (Offline-First PWA):**
  - Нулевые внешние CSS/JS-фреймворки (без Tailwind CDN и Google Fonts), только относительные пути `./`, Service Worker (`Stale-While-Revalidate`) и экспорт/импорт снимков прогноза в JSON.
- **Надёжность и честность данных:**
  - **Поэтапная загрузка:** экран заполняется реальными данными, как только ответил основной канал прогноза (обычно 1–3 с); медленные каналы (почва/снег, MOS, ансамбль 35 дней) догружаются в фоне и не задерживают первый показ.
  - **Канал почвы и снега** кэшируется на 1 час; если сервер не отвечает, используется срез давностью до 12 часов вместо расчёта «по воздуху».
  - **Пометка `≈`:** когда данных модели нет, глубина снега берётся из климатической нормы, а профиль почвы оценивается по температуре воздуха — такие значения и построенные на них выводы (промерзание грунта) явно помечены как оценка.
  - **Контроль состава ансамбля:** модель, вернувшая пустые ряды, отображается в статусе каналов как «Частично», а не выпадает молча. Open-Meteo отдаёт AIFS под идентификатором `ecmwf_aifs025_single`; внутри приложения сохранён стабильный id `ecmwf_aifs025`.
  - **Дальний горизонт (17–35 дней):** ансамбли дают только температуру, осадки и скорость ветра. Давление и направление ветра для этих дней не выдумываются — на графиках линия обрывается с пометкой «нет данных», в таблице стоит «—». Снег (климатическая норма), профиль почвы и точка росы рисуются пунктиром с «≈» и не соединяются линией с модельными данными, чтобы смена источника не выглядела как изменение погоды.
  - **Пятидневки:** все четыре графика и полевая таблица используют одну группировку; отметка скачка давления в этом режиме — наибольшее суточное изменение внутри пятидневки.
  - **Дни 33–35:** если основные ансамбли не покрывают дату, она дополняется сезонным ансамблем; дни без какого-либо ансамбля подписаны «Норма», а не «Тренд».
  - **Автообновление:** данные обновляются при возврате на вкладку, восстановлении сети и не реже раза в 30 минут.
- **Безопасность:**
  - `Content-Security-Policy`: скрипты только со своего origin, сеть — только к метео-API, фреймы — только Windy.
  - Импортируемый JSON и данные из `localStorage` считаются недоверенными: строки очищаются от разметки, числовые поля приводятся к числам, а всё, что попадает в `innerHTML`, экранируется.

│   ├── ensemble.js        # MOS-калибровка, супер-ансамбль 4 зон, квантили 35д, пентады

## Развёртывание на GitHub Pages (3 шага)

1. **Создайте репозиторий на GitHub** (например, `aban-weather`) и отправьте в него файлы проекта:
   ```bash
   git init
   git add .
   git commit -m "feat: Aban Weather v4 PWA"
   git branch -M main
   git remote add origin https://github.com/<ВАШ_ЛОГИН>/aban-weather.git
   git push -u origin main
   ```
2. **Включите GitHub Pages:**
   Откройте **Settings → Pages** в репозитории, в разделе **Build and deployment** выберите `Deploy from a branch`, ветку `main` и папку `/ (root)`. Нажмите **Save**.
3. **Откройте сайт и установите PWA:**
   Через 1–2 минуты приложение станет доступно по адресу `https://<ВАШ_ЛОГИН>.github.io/aban-weather/`. На смартфоне нажмите **«Поделиться → На экран Домой»** (iOS) или **«Установить приложение»** (Android/Chrome).

> Все пути в приложении относительные (`./`), поэтому оно корректно работает как в корне домена, так и в подкаталоге вида `/<repo>/`.

## Настройка ключа Google Weather API (WeatherNext 3)

Приложение полностью работоспособно **без ключа** на базе открытых моделей Open-Meteo (ECMWF IFS/AIFS, ICON, GFS, GEFS, ERA5). При желании можно подключить официальный канал **Google Maps Platform Weather API**:

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект, подключите биллинг (доступен бесплатный лимит) и включите **Weather API** (`weather.googleapis.com`).
2. В разделе **APIs & Services → Credentials** создайте **API Key** и **обязательно ограничьте его (Application restrictions → Websites / HTTP referrers)**:
   - Добавьте ваш домен GitHub Pages: `https://<ВАШ_ЛОГИН>.github.io/*`
   - Для локальной отладки можно временно добавить `http://localhost:*/*` и `http://127.0.0.1:*/*`.
   - В разделе **API restrictions** ограничьте ключ только до **Weather API**.
3. Откройте на сайте **Настройки (⚙️)**, вставьте ключ в поле **Google Weather API Key**, нажмите **«Проверить 10д/240ч»** и **«Сохранить»**. Ключ хранится **исключительно в `localStorage` вашего браузера** и никогда не попадает в Git-репозиторий.

## Локальный запуск и тесты

Для запуска в браузере используйте любой статический HTTP-сервер (ES-модули и Service Worker не работают по `file://`):

```bash
npx serve .
# или
python -m http.server 8080
```

Запуск полного набора тестов и статического аудита (требуется Node.js 20+):

```bash
node --test tests/*.test.mjs
```
